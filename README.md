# 密码箱

一个只给自己用的密码箱：网页版，装到手机桌面上像一个 App，数据加密后存在自己的浏览器里，不联网、不上传。

界面和「我的课表」是同一套风格：**点开就是列表，不问密码**。

---

## 怎么用

### 1. 放到网上（推荐，手机上要用 https 才能装成 App）

和课表一样的做法：新建一个 GitHub 仓库（比如 `password_vault`），把本目录下所有文件传上去，开启 GitHub Pages。
地址会是 `https://你的用户名.github.io/password_vault/`。

### 2. 装到手机桌面

- Android Chrome：打开网址 → 右上角 ⋮ → 「安装应用」或「添加到主屏幕」
- iPhone Safari：分享按钮 → 「添加到主屏幕」

装好后点图标就是全屏，没有地址栏，和 App 一样。

### 3. 打开就是列表

没有主密码这一步。第一次打开会自动建一个空箱子，直接开始加条目：标题、账号、密码/密钥、网址、文件夹、标签、备注。

> 从旧版升级上来的会**要一次**原来的主密码，输对之后改成打开即用，以后不再问。

### 4. 分文件夹

列表上方有一排「全部 / 未分类 / 文件夹名」，点一下只看那一类，后面的数字是条数。

- **建文件夹**：编辑条目时，把「文件夹」下拉拉到最下面选「＋ 新建文件夹…」，填名字回车（或点「建好」）就行，不用先去别处创建
- **改归属**：编辑条目时在同一个下拉里换
- **改名 / 删除**：设置 → 文件夹，点「改名」直接就地改；点「删除」时里面条目会**回到未分类**，条目本身不会被删
- 当前正筛着某个文件夹时点「+」，新条目会默认落进那个文件夹

条目和文件夹一起加密，加密后看磁盘上同样只有一团密文。

### 5. 备份

设置 → 备份。两条路：

**手机**：点「存到手机…」会弹系统的保存/分享面板，选「保存到文件」自己挑位置，这样最可靠。点「导出备份」是直接下载，安卓浏览器常把它扔进自己的下载目录，事后不好找（一般是 `文件管理 → Download`），文件名带日期（`密码箱备份-2026-11-05.json`）。两个都不行就点「复制备份内容」，粘进备忘录——那段文字本身就是备份。

浏览器不允许网页打开文件管理器或跳转到本地文件夹，所以「点一下就跳过去」这件事网页做不到。

**电脑（Chrome / Edge）**：点「选文件夹」选一次目录（比如 `D:\备份\密码箱`），之后每次点「存进这个文件夹」就直接写进去，**不再弹保存框**。这个权限被浏览器记住了，换电脑要重新选。

界面上会显示「上次备份：N 天前」，超过 14 天变橙色提醒。

## 安全说明（重要，请读完）

### 现在的保护是什么

```
本机钥匙（随机 32 字节，存在这台浏览器里）
  └─ PBKDF2-SHA256，60 万次迭代 + 16 字节随机盐   → 256 位密钥
       └─ AES-256-GCM 加密整份数据（每次保存换新 IV）
            └─ 只把这堆密文写进浏览器的 localStorage
```

- 数据在磁盘上**仍然是密文**：打开开发者工具 → Application → Local Storage，看到的是 `format`、`version`、`kdf`、`data`，没有明文
- 但钥匙就放在同一台机器的 localStorage 里（`vault.device.v1`）。**锁和钥匙挂在一起**，所以真正的门是手机的锁屏和你的浏览器
- 密文被改动一个字节，解密就会失败（不会悄悄给你错误数据）
- 备份文件里带着这把钥匙（`deviceKey` 字段），换手机能直接恢复

### 它能防什么

- 网站服务器被入侵 → 服务器上根本没有你的数据
- 随手翻看 localStorage、浏览器缓存、设备备份文件 → 看到的是乱码
- 手机丢了、别人打不开你的锁屏 → 打不开

### 它防不了什么（别高估它）

1. **拿到你手机并且能解锁的人**：能打开这台手机，就能看到全部内容。这是你自己选的取舍。
2. **备份文件泄漏**：备份里带着钥匙，谁拿到这个 json，谁就能读。放网盘要选私密目录，别丢群聊里。
3. **网页被篡改**：它是网页，每次打开都会加载服务器上的 JS。托管平台被入侵、你的 GitHub 账号被盗、网络被动手脚，都可能被推一版「顺手把密码发走」的 JS。
4. **浏览器扩展**：有权限读取页面的插件能看到页面内容。
5. **清缓存**：localStorage 属于「网站数据」，清浏览器数据、卸载浏览器、iOS 长期不用自动清理，都会让数据消失。

### 所以请务必

- **定期导出备份**（设置 → 导出备份），放在只有你能拿到的地方；电脑上可以先「选文件夹」，之后一键写入
- 真正贵重的东西（比如能花钱的 API Key）**同时在别处留一份**，别只信一个网页
- 不要在公共电脑上用它，也不要把备份文件发给别人

想更安全一点：把它用 Capacitor 打包成真正的本地 App（代码不用改），或者干脆把这几个文件放在自己电脑上离线打开。

**想把主密码加回来**：改 `app.js` 里的 `deviceKey()`，把「自动生成并存 localStorage」换成「弹窗问一句再返回」，别的都不用动。

## 数据长什么样

浏览器里存两样东西：

`vault.file.v1`（密文保险箱）：

```json
{
  "format": "my-vault",
  "version": 1,
  "kdf": { "algo": "PBKDF2-SHA256", "iterations": 600000, "salt": "…" },
  "data": { "iv": "…", "ct": "…" },
  "updatedAt": "2026-11-02T12:00:00.000Z"
}
```

`vault.device.v1`（本机钥匙，44 字符 base64；删了它等于换了一把新钥匙，旧密文就打不开了）。

导出的备份 = 上面的 `vault.file.v1` 再加一个 `"deviceKey": "…"` 字段。

解开后的明文结构：

```js
{
  folders: [
    { id: 'f1', name: '代码' }
  ],
  entries: [
    {
      id: '…',
      title: 'GitHub',
      username: 'you@example.com',
      secret: 'ghp_xxx',        // 密码、API Key、私钥都放这里
      url: 'github.com',
      folderId: 'f1',           // 没有就是 null（未分类）
      tag: '代码',
      note: '2027-01 过期',
      createdAt: '…',
      updatedAt: '…'
    }
  ]
}
```

## 改代码

| 文件 | 作用 |
| --- | --- |
| `index.html` | 页面结构：列表页、三个弹层（旧版迁移页只在升级时出现） |
| `style.css` | 样式，跟随系统深色模式 |
| `vault.js` | 加密核心：派生密钥、加解密、密码生成器 |
| `app.js` | 界面逻辑：本机钥匙、增删改、搜索、文件夹 |
| `manifest.json` | 装成 App 的配置 |
| `sw.js` | 离线缓存 |
| `icons/` | 图标（`make-icons.py` 用 Pillow 生成） |

### 改完要更新缓存

和课表一样：改完文件，把 `sw.js` 第 4 行 `vault-v5` 改成 `vault-v6`，再一起上传，否则手机上还是旧版本。

### 想调参数

- 觉得慢/想更安全：改 `vault.js` 里的 `KDF_ITERATIONS`（默认 600000）
- 备份文件里要不要带钥匙：`app.js` 的 `exportBackup()`，删掉 `deviceKey: …` 那一项就变成「只有本机能开」的备份

## 常见问题

**换手机怎么迁移？**
旧手机：设置 → 导出备份，把 json 传过去；新手机：打开网址 → 设置 → 导入备份 → 直接就能看，不用输密码。

**别人也装了这个网站，会不会和我的混在一起？**
不会。这是纯静态网页，没有服务器、没有账号、没有同步。数据只存在「他自己的浏览器」里，和你那份互不相干。

**同一个手机、不同浏览器打开，看到的是同一份吗？**
不是。数据按浏览器分开存，Chrome 和 Edge 各有一份。

**要是把网址发给朋友呢？**
他自己打开是空的，自己用自己的一份。你不导出发给他，你的东西不会过去。

**数据丢了怎么办？**
只能靠备份。所以养成改完就导一份的习惯。
