# 密码箱

一个只给自己用的密码箱：网页版，装到手机桌面上像一个 App，数据全部加密后存在自己的浏览器里，不联网、不上传。

界面和「我的课表」是同一套风格，操作逻辑也一样：打开 → 输主密码 → 看到列表。

---

## 怎么用

### 1. 放到网上（推荐，手机上要用 https 才能装成 App）

和课表一样的做法：新建一个 GitHub 仓库（比如 `password_vault`），把本目录下所有文件传上去，开启 GitHub Pages。
地址会是 `https://你的用户名.github.io/password_vault/`。

### 2. 装到手机桌面

- Android Chrome：打开网址 → 右上角 ⋮ → 「安装应用」或「添加到主屏幕」
- iPhone Safari：分享按钮 → 「添加到主屏幕」

装好后点图标就是全屏，没有地址栏，和 App 一样。

### 3. 第一次打开

会让你**设置主密码**。这个密码：

- 不存到任何地方，只在你脑子里
- 忘了就**真的打不开**，没有任何找回方式，也没有后门
- 建议至少 12 位，用一句话（比如 `蓝色 冰箱 跑得 很快 2026`）比乱码好记又安全

设好之后就能加条目了：标题、账号、密码/密钥、网址、文件夹、标签、备注。

### 4. 分文件夹

列表上方有一排「全部 / 未分类 / 文件夹名」，点一下只看那一类，后面的数字是条数。

- **建文件夹**：编辑条目时，把「文件夹」下拉拉到最下面选「＋ 新建文件夹…」，填名字回车（或点「建好」）就行，不用先去别处创建
- **改归属**：编辑条目时在同一个下拉里换
- **改名 / 删除**：设置 → 文件夹，点「改名」直接就地改；点「删除」时里面条目会**回到未分类**，条目本身不会被删
- 当前正筛着某个文件夹时点「+」，新条目会默认落进那个文件夹

条目和文件夹一起加密，加密后看磁盘上同样只有一团密文。

## 安全说明（重要，请读完）

### 加密是怎么做的

```
主密码
  └─ PBKDF2-SHA256，60 万次迭代 + 16 字节随机盐   → 256 位密钥
       └─ AES-256-GCM 加密整份数据（每次保存换新 IV）
            └─ 只把这堆密文写进浏览器的 localStorage
```

- 主密码本身**从不存储**，也不参与存储的比对；密码对不对，靠 AES-GCM 的认证标签来判断
- 密文被改动一个字节，解密就会失败（不会悄悄给你错误数据）
- 改主密码时会换新盐、重新加密全部内容，旧密码立刻失效

你可以在浏览器开发者工具 → Application → Local Storage 里看到存的东西：只有 `format`、`version`、`kdf`、`data`，没有任何明文。

### 它能防什么

- 手机丢了、电脑被人翻到 → 没有主密码打不开
- 备份文件被人拿到（比如放网盘）→ 同样是密文，没有主密码打不开
- 网站服务器被入侵 → 服务器上根本没有你的数据

### 它防不了什么（别高估它）

1. **网页被篡改**：因为它是网页，每次打开都会加载服务器上的 JS。如果托管平台被入侵、你的 GitHub 账号被盗、或者有人在你的网络里动了手脚，攻击者可以推一版「顺手把密码发走」的 JS。这是所有网页版密码管理器共同的弱点。
2. **浏览器扩展**：有权限读取页面的插件能看到你在输入什么。
3. **设备本身被入侵**：键盘记录器、木马、root 过的手机。
4. **清缓存**：localStorage 属于「网站数据」，清浏览器数据、卸载浏览器、iOS 长期不用自动清理，都会让数据消失。

### 所以请务必

- **定期导出备份**（设置 → 导出备份），导出的文件是密文，放网盘也行
- 真正贵重的东西（比如能花钱的 API Key）**同时在别处留一份**，别只信一个网页
- 不要在公共电脑上用它

想更安全一点：把它用 Capacitor 打包成真正的本地 App（代码不用改），或者干脆把这几个文件放在自己电脑上离线打开。

## 数据长什么样

浏览器里只存一个 JSON（`vault.file.v1`）：

```json
{
  "format": "my-vault",
  "version": 1,
  "kdf": { "algo": "PBKDF2-SHA256", "iterations": 600000, "salt": "…" },
  "data": { "iv": "…", "ct": "…" },
  "updatedAt": "2026-11-02T12:00:00.000Z"
}
```

解开后的明文结构：

```js
{
  folders: [
    { id: 'f1', name: '代码' }
  ],
  entries: [
    {
      id: '…',
      title: 'GitHub',
      username: 'you@example.com',
      secret: 'ghp_xxx',        // 密码、API Key、私钥都放这里
      url: 'github.com',
      folderId: 'f1',           // 没有就是 null（未分类）
      tag: '代码',
      note: '2027-01 过期',
      createdAt: '…',
      updatedAt: '…'
    }
  ]
}
```

## 改代码

| 文件 | 作用 |
| --- | --- |
| `index.html` | 页面结构：解锁页、列表页、三个弹层 |
| `style.css` | 样式，跟随系统深色模式 |
| `vault.js` | 加密核心：派生密钥、加解密、密码生成器 |
| `app.js` | 界面逻辑：解锁、增删改、搜索、文件夹、自动锁定 |
| `manifest.json` | 装成 App 的配置 |
| `sw.js` | 离线缓存 |
| `icons/` | 图标（`make-icons.py` 用 Pillow 生成） |

### 改完要更新缓存

和课表一样：改完文件，把 `sw.js` 第 4 行 `vault-v2` 改成 `vault-v3`，再一起上传，否则手机上还是旧版本。

### 想调参数

- 觉得解锁慢/想更安全：改 `vault.js` 里的 `KDF_ITERATIONS`（默认 600000）
- 默认自动锁定时间：`app.js` 里 `prefs.autoLock` 初始值（默认 5 分钟）

## 常见问题

**忘了主密码怎么办？**
没有任何办法。设计上就没有后门。只能清空重建（设置 → 清空所有数据）。

**换手机怎么迁移？**
旧手机：设置 → 导出备份，把 json 文件传过去；新手机：打开网址 → 设置 → 导入备份 → 用备份的主密码解锁。

**为什么不用浏览器自带的密码管理器？**
那种会把密码同步到厂商服务器。这个只存本地，代价是得自己备份。

**能不能加指纹解锁？**
网页版可以用 WebAuthn，但实现要在本地再包一层密钥管理，复杂度高。真需要的话再单独做。
